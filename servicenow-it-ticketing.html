ServiceNow · IT Service Management done

An IT support ticketing app, built as a scoped ServiceNow application

A ticketing system built from scratch on the ServiceNow platform. It covers the full lifecycle of a support ticket, from creation and routing through validation, notification, and resolution.

Scoped Application Development

Data model

The app lives in its own scope, with custom tables for tickets, reference and choice fields for requesters, categories, and priority, and automated ticket numbering. Resolution tracking is built into the record, so every ticket carries its own history of when and how it was closed.

Form behaviour on the client

  • Client Scripts drive dynamic form behaviour, such as a warning when a ticket is marked critical priority.
  • UI Policies make resolution details required only when the ticket is actually being resolved, so the form asks for information at the moment it matters.

Rules on the server

  • Business Rules stamp the resolution timestamp automatically, so it never depends on someone remembering to fill it in.
  • A validation rule blocks a ticket from being resolved unless it has been assigned, which keeps ownership clear on every closed ticket.

Live open-ticket count

When a requester is selected, the form shows how many tickets they already have open. A client-callable Script Include queries the ticket table with GlideRecord, and the form calls it through GlideAjax, so the count updates without a page reload. It gives support staff context before they start working on a new request.

Routing and notifications

Assignment groups route tickets to the right support team, and the assignee field depends on the chosen group, so only members of that group can be picked. Email notifications go out to assignees whenever an assignment changes.

Testing

I tested the whole flow end to end: ticket creation, assignment, client and server-side validation, notifications, and resolution. That way each rule was checked against the others, not just on its own.
