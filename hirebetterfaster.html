HireBetterFaster: hybrid retrieval and bias checks for an AI hiring platform

HireBetterFaster.com is an AI hiring platform. As its AI Specialist, I built the retrieval layer behind resume Q&A and candidate ranking, the LLM workflows that pull structured data out of documents, and the tooling that keeps candidate scoring fair.

AI Specialist · HireBetterFaster.com

Hybrid retrieval

Semantic search alone misses exact terms like a specific framework or certification, and keyword search alone misses paraphrases. So the retrieval layer runs both:

  • Semantic search uses BAAI/bge-small-en-v1.5 embeddings stored in PostgreSQL with pgvector.
  • Keyword search uses PostgreSQL full-text search over the same documents.
  • Reciprocal Rank Fusion (RRF) merges the two ranked lists into one, without having to calibrate their scores against each other.

LLM extraction workflows

Metadata and skill extraction run on Groq using qwen/qwen3-32b. The model emits its reasoning trace alongside the answer, and that trace was being carried into downstream steps as wasted tokens. I wrote custom regex sanitization to strip it from the output, which cut token overhead by more than 30%.

Fairness: FairLens Enhance

FairLens Enhance is a bias-detection engine I designed for job postings. It flags gendered and age-coded language before a posting goes out.

On the candidate side, a PII-stripping pipeline removes name, location, email, and gender before any scoring happens, so the model never sees them. Each evaluation also produces an auto-generated fairness audit report.

What actually mattered

  • Hybrid retrieval with RRF is a cheap, robust default. It catches what each retriever misses on its own, with no score tuning.
  • Reasoning models need output hygiene. Stripping the thinking trace saved tokens on every downstream call.
  • Fairness has to be built into the pipeline itself. Removing PII before scoring is a structural guarantee, not a policy someone has to remember.
